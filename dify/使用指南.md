# Dify 日志查询工具入门指南

这是一款运行在命令行中的 Dify Console 辅助工具，可以查询 Workflow 日志、统计 Token 消耗，以及检查业务组中当天失败的 Run。

本文专门写给**不懂编程、没有使用过 Git** 的同事，以 Windows 电脑为例。你不需要看懂命令的含义，只要按顺序操作，并且每次只复制一个命令即可。

## 先看这里：最快使用路线

第一次使用通常只需要完成下面 5 件事：

1. 安装 Python。
2. 下载程序 ZIP 压缩包并解压。
3. 在解压后的 `dify` 文件夹中打开 PowerShell。
4. 复制本文提供的命令安装依赖，再填写 Dify 地址和登录凭证。
5. 运行工具。

配置完成后，日常使用只需要打开 `dify` 文件夹并运行一条命令：

```powershell
.\.venv\Scripts\python.exe main.py
```
## 一、开始前需要准备什么

请先确认你拥有：

1. 一台 Windows 电脑。
2. 能正常登录目标 Dify Console 的账号。
3. 安装软件和解压文件的权限。
4. Python 3.10 或更高版本（下面会说明如何检查和安装）。

检查 Python 是否已经安装：

1. 按 `Win + R`。
2. 输入 `powershell`，按回车。
3. 在打开的窗口中输入：

```powershell
python --version
```

如果显示类似 `Python 3.12.4`，说明已经安装。只要版本不低于 3.10 即可。

如果显示类似 `Python 3.9`，版本太低，也需要安装新版本。

如果提示找不到 `python`：

1. 前往 [Python 官方网站](https://www.python.org/downloads/)下载 Windows 安装程序。
2. 双击安装程序。
3. 在第一个安装界面勾选 **Add python.exe to PATH**。
4. 点击 **Install Now**。
5. 安装完成后，关闭原来的 PowerShell 窗口，重新打开一个窗口。
6. 再次执行 `python --version`。

## 二、解压工具包

同事发给你的 ZIP 压缩包中只包含一个 `dify` 文件夹：

1. 右键 ZIP 压缩包，选择“全部解压”。不要直接在压缩包预览窗口中运行工具。
2. 打开解压后的 `dify` 文件夹。
3. 确认文件夹中能看到 `main.py`、`config.yaml` 和 `requirements.txt`。
4. 点击文件资源管理器顶部的地址栏，输入 `powershell`，然后按回车。

此时会打开一个蓝色或黑色的命令窗口。**不要关闭这个窗口**，后面的安装和运行命令都在这里输入。

可以输入下面的命令确认当前位置：

```powershell
Get-Location
```

显示的路径末尾应当是 `dify`。如果不是，请关闭窗口，回到包含 `main.py` 的 `dify` 文件夹，再按第 4 步重新打开 PowerShell。

## 三、安装依赖

### 1. 创建独立的 Python 环境

```powershell
python -m venv .venv
```

这条命令会在当前目录创建 `.venv` 文件夹，避免本工具的依赖影响电脑上的其他 Python 项目。

命令执行完成时可能没有任何提示，只要没有出现红色错误信息，就可以继续下一步。

### 2. 安装依赖

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

等待命令执行完并重新出现以 `PS` 开头的输入提示。看到 `Successfully installed`，或者没有红色错误信息，通常就表示安装成功。以后运行工具时，直接使用 `.venv` 中的 Python，不需要每次激活虚拟环境。

如果下载速度慢，可以稍后重试，或联系网络管理员确认是否需要设置代理。

## 四、配置 Dify 地址

在 PowerShell 中执行下面的命令，用记事本打开配置文件：

```powershell
notepad config.yaml
```

在打开的文件中找到：

```yaml
instance:
  name: dify-production
  base_url: https://你的-dify-地址.example.com
  timezone: Asia/Shanghai
  workspace_id: 00000000-0000-0000-0000-000000000001
```

第一次只需要修改下面 3 项，其他内容保持原样：

- `name`：给当前 Dify 环境起一个便于识别的名称。
- `base_url`：浏览器中访问 Dify Console 使用的地址，不要在末尾添加 `/`。
- `workspace_id`：可选。只有一个 Workspace 时可以留空；有多个 Workspace 时建议填写，用来防止查询到另一套应用。

### 获取 Workspace ID

如果账号**只有一个 Workspace**，可以不填写 ID，改成下面这样：

```yaml
instance:
  workspace_id: ""
```

留空后工具会跳过 Workspace 校验，不影响其他查询功能。

如果账号有多个 Workspace，或者希望工具在 Workspace 切换错误时主动停止，建议填写 ID。获取方法：

1. 登录目标 Dify Workspace。
2. 按 `F12` 打开开发者工具。
3. 进入 **网络（Network）** 面板并刷新页面。
4. 找到 `/console/api/workspaces` 请求。
5. 查看响应内容，找到 `"current": true` 的对象。
6. 复制该对象的 `id`，填入 `config.yaml` 的 `workspace_id`。

程序启动时会显示类似 `Workspace 校验成功：GenCare`。如果网页切换到了其他 Workspace，程序会明确提示当前值与配置值不一致，并停止执行，不会继续请求错误的应用 ID。

初次使用时，其他参数可以保持默认值。

## 五、配置认证信息

不同 Dify 域名的认证方式可能不同：有的使用 Cookie 和 CSRF，有的使用 `Authorization` 请求头。工具支持这两种方式，但需要先告诉工具当前实例使用哪一种。

### 1. 判断认证方式

1. 在浏览器中登录目标 Dify Console。
2. 按 `F12` 打开开发者工具。
3. 选择 **网络（Network）** 面板并刷新页面。
4. 打开一个地址包含 `/console/api/` 的请求。
5. 查看 **请求标头（Request Headers）**。

按下面的规则判断：

- 请求同时包含 `Cookie` 和 `X-CSRF-Token`：选择 Cookie 认证。
- 请求包含 `Authorization`，且服务主要依赖它认证：选择 Authorization 认证。
- 无法判断时，可以咨询该 Dify 环境的管理员。

### 2. 在 `config.yaml` 中选择认证方式

Cookie 认证：

```yaml
authentication:
  type: cookie
```

Authorization 认证：

```yaml
authentication:
  type: authorization
```

只能填写小写的 `cookie` 或 `authorization`。切换 Dify 域名时，记得同时检查这里的配置。

### 3. 创建 `.env` 文件

在 PowerShell 中执行：

```powershell
Copy-Item .env.example .env
```

然后执行下面的命令，用记事本打开它：

```powershell
notepad .env
```

如果记事本询问是否创建新文件，说明上一条复制命令没有成功。请选择“否”，回到 PowerShell 检查当前是否在 `dify` 文件夹中。

### 4. 保存认证信息

#### 使用 Cookie 认证

以 Chrome 或 Edge 为例：

1. 在浏览器中登录 Dify Console。
2. 按 `F12` 打开开发者工具。
3. 选择 **网络（Network）** 面板。
4. 刷新 Dify 页面。
5. 在请求列表中选择一个地址包含 `/console/api/` 的请求，例如 `apps` 请求。
6. 在右侧选择 **标头（Headers）**。
7. 找到 **请求标头（Request Headers）** 中的 `Cookie`。
8. 复制 `Cookie` 的完整值。

正确的 Cookie 通常包含多个由分号分隔的字段，并且必须包含：

```text
__Host-csrf_token=...
```

把完整 Cookie 粘贴到 `.env` 的双引号中：

```env
DIFY_COOKIE="这里粘贴完整 Cookie"
```

#### 使用 Authorization 认证

在刚才打开的 `/console/api/` 请求中找到 `Authorization`。复制冒号后面的完整值到 `.env` 文件中。

```env
DIFY_AUTHORIZATION="Bearer eyJ..."
```

## 六、第一次运行

在 `dify` 文件夹中执行：

```powershell
.\.venv\Scripts\python.exe main.py
```

正常情况下，程序会先检查配置、Workspace 和认证信息，然后显示主菜单。第一次连接需要几秒钟，请等待窗口重新出现提示，不要连续重复按回车。

认证成功后，会看到类似菜单：

```text
┌─ Dify 日志查询工具 · 当前 [1]
│  ↑/↓ 移动  ·  输入数字跳转  ·  Enter 确认  ·  Q 退出
│
│  › [1] 查询 · Workflow
│    [2] 查询 · Chatflow
│    [3] 检查 · 失败的 Run
│    [4] 管理 · 业务组
│    [5] 统计 · 示例组 Token 消耗
│    [0] 退出
└─ [Q] 退出
```

所有单选菜单都支持两种操作方式：

- 按 `↑`、`↓` 移动蓝色焦点，标题中的“当前编号”会同步变化，按回车确认。
- 直接输入数字，焦点会立即跳到对应编号，再按回车确认；两位数编号也支持，例如连续输入 `1`、`0` 会定位到 `[10]`。

输入 `0`、按 `Q` 或按 `Esc` 可以返回或退出。在主菜单直接按回车等同于选择 `[1]`。非交互环境仍使用原来的“输入数字后按回车”方式，便于 AI Agent 和脚本操作。

如果程序提示粘贴最新认证值，可直接在窗口中粘贴并按回车。提示内容会根据 `authentication.type` 显示 Cookie 或 Authorization。出于安全考虑，输入内容不会显示，这是正常现象。程序验证成功后会自动更新 `.env`。

如果没有出现菜单，请不要双击 `main.py` 重试。保留 PowerShell 中的完整报错，并到本文“常见问题”查找对应提示；仍无法解决时，将**报错文字**发给维护人员，但不要发送 `.env` 内容。

## 七、各项功能怎么用

### 查询 Workflow 日志

1. 在主菜单输入 `1`。
2. 输入 Workflow 名称中的一部分；直接回车会显示全部 Workflow。
3. 输入应用前面的编号。
4. 选择“查看最近日志”或“统计最近 Token 消耗”。
5. 查看日志时，还可以继续选择某一条运行记录查看详情。

查看运行详情后，完整响应会保存为当前目录下的 `workflow_run_运行ID.json` 文件。该文件可能包含业务输入和输出，分享前请检查敏感信息。

### 查询 Chatflow Token 消耗

1. 在主菜单输入 `2`。
2. 输入 Chatflow 名称关键字，或者直接回车显示全部。
3. 选择一个应用。
4. 选择统计范围：今天、昨天、最近 3 天或最近 7 天。

### 检查失败的 Run

1. 在主菜单输入 `3`。
2. 选择“全部分组”，或选择某一个业务组。
3. 等待检查完成。

报告会列出检查的应用数、失败 Run 数量和失败应用。看到“未发现失败运行”表示所选范围内没有查询到失败记录。

### 统计整个业务组的 Token

主菜单中从编号 `5` 开始的选项来自业务组配置。例如输入 `5`，就会统计菜单中对应业务组的 Token 消耗。

结果中带 `~` 的数字是根据样本估算的近似值，不代表精确总量。

### 退出程序

在主菜单输入 `0`。在部分子菜单中，直接按回车可以取消当前操作并返回上一级。

## 八、管理业务组

业务组用于批量统计 Token 和检查失败 Run。

### 使用菜单管理（推荐）

在主菜单输入 `4`，会看到：

```text
┌─ 管理业务组
│  [1] 查看业务组
│  [2] 新增业务组
│  [3] 修改业务组及应用
│  [4] 删除业务组
└─ [0] 返回主界面
```

#### 新增业务组并添加应用

1. 输入 `2`。
2. 输入分组代号，例如 `customer_service`。代号只能使用英文字母、数字、下划线和短横线。
3. 输入显示名称，例如“客服组”。
4. 回到管理菜单后输入 `3`，再选择刚创建的业务组。
5. 输入 `3` 选择“添加应用”。
6. 输入应用名称中的一部分；直接按回车会列出全部应用。
7. 使用键盘的 `↑`、`↓` 方向键移动焦点，当前焦点行会显示为蓝色。
8. 按空格键选中或取消应用；可以连续勾选多个应用，选中项会以绿色显示 `[✓]`。
9. 选好后按回车统一确认。按 `Q` 或 `Esc` 可以取消。

工具会一次性保存所有选中应用的名称、ID 和类型，不需要手动查找 UUID。已经在当前业务组中的应用不会重复显示。保存后，业务组的 Token 统计选项会自动出现在主菜单中。

> 如果当前运行环境不支持方向键列表，工具会自动显示编号；输入多个编号并用逗号分隔即可，例如 `1,3,5`。

#### 查看、修改或删除

- 输入 `1`：查看所有业务组、分组代号和组内应用。
- 输入 `3`：修改分组代号或显示名称，也可以添加、移除组内应用。
- 输入 `4`：删除整个业务组，需要输入大写的 `DELETE` 才会执行。

移除应用或删除业务组只会修改本地的 `dify_flow_groups.json`，**不会删除 Dify Console 中的真实应用**。同一个应用也可以加入不同业务组，但不能在同一业务组中重复添加。

### 手动编辑配置（可选）

熟悉 JSON 的用户也可以先复制示例文件：

```powershell
Copy-Item dify_flow_groups.example.json dify_flow_groups.json
```

然后编辑 `dify_flow_groups.json`：

```json
{
  "groups": {
    "customer_service": {
      "display_name": "客服组",
      "apps": [
        {
          "name": "客服问答",
          "app_id": "00000000-0000-0000-0000-000000000001",
          "mode": "advanced-chat"
        },
        {
          "name": "工单摘要",
          "app_id": "00000000-0000-0000-0000-000000000002",
          "mode": "workflow"
        }
      ]
    }
  }
}
```

字段含义：

| 字段               | 说明                       | 示例                                  |
| ------------------ | -------------------------- | ------------------------------------- |
| `customer_service` | 分组代号，命令行检查时使用 | `customer_service`                    |
| `display_name`     | 主菜单和报告中显示的名称   | `客服组`                              |
| `name`             | 应用名称，仅用于报告展示   | `客服问答`                            |
| `app_id`           | Dify 应用的 UUID           | `00000000-...`                        |
| `mode`             | 应用类型                   | `workflow`、`advanced-chat` 或 `chat` |

应用 ID 通常可以从 Dify 应用编辑页面的网址中找到。例如网址包含 `/app/1234.../workflow`，其中 `1234...` 就是应用 ID。使用菜单添加应用时不需要自己查找 ID。

注意：

- JSON 中的字段名和文字必须使用英文双引号。
- 同一组中的每个应用之间要有英文逗号。
- 最后一项后面不能多写逗号。
- `dify_flow_groups.json` 可能包含内部应用名称和 ID，不要公开分享。

保存后重新启动程序，新分组会自动出现在主菜单中。

## 九、使用 `--check-failures` 快速检查

不进入菜单，直接检查某个业务组当天的失败 Run：

```powershell
.\.venv\Scripts\python.exe main.py --check-failures customer_service
```

一次检查多个组时，用空格分隔分组代号：

```powershell
.\.venv\Scripts\python.exe main.py --check-failures customer_service knowledge_search
```

这里使用的是 `dify_flow_groups.json` 中 `groups` 下的分组代号，不是 `display_name`。

### 认证信息过期时会发生什么

在 Windows 上运行 `--check-failures` 时，如果检测到 Cookie 或 Authorization 过期：

1. 程序会自动打开一个新的认证信息输入窗口。
2. 根据提示粘贴完整 Cookie 或 Authorization 值，然后按回车。
3. 输入内容不会显示，这是正常的安全设计。
4. 验证成功后，新窗口会自动关闭，无需手动关闭。
5. 原窗口会自动继续检查失败 Run。

如果认证信息格式错误或验证失败，新窗口会保留错误提示。按照提示重新输入；如果最终失败，按回车关闭窗口后重新运行命令。

> Linux 和 macOS 当前不会自动打开新的认证信息窗口。请先在 `.env` 中更新认证值，再重新执行检查命令。

## 十、可选：调整统计配置

普通用户可以保持 `config.yaml` 中的默认设置。遇到速度或请求频率问题时，再考虑调整以下参数：

| 参数                                    | 作用                      | 调整建议                     |
| --------------------------------------- | ------------------------- | ---------------------------- |
| `collection.apps_page_size`             | 每次读取多少个应用        | 通常保持默认值               |
| `collection.interactive_log_limit`      | 菜单中显示多少条最近日志  | 数字越大，等待时间可能越长   |
| `collection.monitor_page_size`          | 失败检查每页读取数量      | 通常保持默认值               |
| `collection.token_stats_workers`        | 同时统计多少个应用        | 遇到 HTTP 429 时调小         |
| `token_statistics.workflow_sample_size` | Workflow Token 估算样本量 | 越大越接近实际值，但查询更慢 |

修改正整数参数时必须填写大于 `0` 的整数。

## 十一、常见问题

### 提示“缺少 `__Host-csrf_token`”

复制的 Cookie 不完整。请从 `/console/api/` 请求的 Request Headers 中重新复制完整 Cookie。

### 提示 HTTP 401 或 HTTP 403

认证信息已过期、Cookie 与 CSRF 信息不匹配，或者当前账号没有访问该应用的权限。先确认 `authentication.type` 与浏览器请求一致，再重新复制对应的 Cookie 或 Authorization 值。

### 配置了 Authorization 但仍提示缺少 Cookie

检查 `config.yaml` 是否包含以下内容，并确认缩进正确：

```yaml
authentication:
  type: authorization
```

修改配置后需要退出并重新启动程序。

### 提示“当前 Workspace 与配置不一致”

同一个 Dify 账号的当前 Workspace 保存在服务端。即使 Cookie 没有变化，在网页上切换 Workspace 也会影响脚本查询结果。请按照错误提示在网页中切回正确的 Workspace，再重新运行程序；不要随意把 `workspace_id` 改成错误 Workspace 的 ID。

### 提示 HTTP 429

请求太频繁。等待一段时间后重试，并适当调小 `config.yaml` 中的 `collection.token_stats_workers`。

### 提示找不到业务组

检查命令中填写的是否为分组代号。例如配置是 `"customer_service": {...}`，命令中就要写 `customer_service`，不能写显示名称“客服组”。

### 主菜单中找不到某个应用

可能的原因：

- 输入的名称关键字不匹配。
- 当前登录账号没有该应用的查看权限。
- 应用类型与所选菜单不一致，例如 Chatflow 应用不会出现在 Workflow 列表中。

### PowerShell 不允许激活虚拟环境

本指南中的命令直接运行 `.venv\Scripts\python.exe`，不需要激活虚拟环境，因此不受 PowerShell 执行策略影响。

### 中文显示乱码

建议使用 Windows Terminal 或新版 PowerShell。也可以先执行：

```powershell
chcp 65001
```

然后重新运行工具。

### 程序一闪而过

不要双击 `main.py`。请先打开 PowerShell，进入 `dify` 文件夹，再输入本文中的运行命令，这样才能看到完整错误信息。

### 输入 `python` 后打开了 Microsoft Store

这通常表示 Python 没有正确安装，或者 Windows 的“应用执行别名”抢占了命令。先按照第一节重新安装 Python，并确保勾选 **Add python.exe to PATH**。如果仍然发生，请在 Windows 设置中搜索“应用执行别名”，关闭 `python.exe` 和 `python3.exe` 的应用安装程序别名，然后重新打开 PowerShell。

### 提示找不到 `requirements.txt` 或 `main.py`

当前打开的不是正确文件夹。关闭 PowerShell，在文件资源管理器中找到同时包含 `main.py`、`config.yaml` 和 `requirements.txt` 的 `dify` 文件夹，再在地址栏输入 `powershell` 并按回车。

### 安装依赖时出现网络、证书或超时错误

先确认电脑可以访问互联网，然后重新执行安装命令。公司网络可能需要代理或使用内部软件源；如果重复失败，请把 PowerShell 中从 `ERROR` 开始的报错文字发给 IT 或维护人员，不要只发送截图中的最后一行。

## 十二、安全提醒

- `.env`、Cookie 和 Authorization 都是敏感信息，不要上传、转发或截图分享。
- 不要把包含真实应用名称和 ID 的 `dify_flow_groups.json` 发到公共场合。
- 导出的运行详情 JSON 可能包含用户输入和模型输出，发送前必须检查内容。
- 离开电脑或不再使用工具时，应退出 Dify 账号，让旧认证信息失效。

## 十三、最短操作清单

已经完成配置后，每天只需要：

1. 在文件资源管理器中打开本工具的 `dify` 文件夹。
2. 点击顶部地址栏，输入 `powershell`，按回车。
3. 在打开的窗口中执行：

```powershell
.\.venv\Scripts\python.exe main.py
```

如果只想检查失败 Run：

```powershell
.\.venv\Scripts\python.exe main.py --check-failures 分组代号
```

遇到认证信息过期，按窗口提示粘贴新 Cookie 或 Authorization 值即可。验证成功后窗口会自动关闭，检查会继续执行。

### 收到新版本时怎么更新

收到新版 ZIP 工具包后：

1. 不要删除原来的 `dify` 文件夹，先把它改名为 `dify-旧版`，这样配置还能找回。
2. 解压新版 ZIP，得到新的 `dify` 文件夹。
3. 从 `dify-旧版` 中复制自己的 `.env` 和 `dify_flow_groups.json` 到新版 `dify` 文件夹。
4. 同时打开新旧两个 `config.yaml`，把旧版中的 Dify 地址、Workspace ID、认证方式等个人配置填写到新文件中。不要直接覆盖新版文件，因为新版本可能增加配置项。
5. 在新版 `dify` 文件夹中重新执行“第三节：安装依赖”的两个命令。
6. 运行工具，确认菜单和查询功能正常后，再自行删除旧版文件夹。

复制 `.env` 时，文件资源管理器可能默认不显示它。可点击“查看”→“显示”→“隐藏的项目”。`.venv` 不需要复制，运行详情 JSON 等导出文件也不要误当成配置文件。
